## Практические рекомендации

### Когда использовать RAG

✅ **Эффективно для:**
- Специализированных доменов (медицина, право, техническая документация)
- Корпоративных баз знаний
- Актуальной информации (новости, обновления продуктов)
- Проверяемых фактов (научные публикации, отчеты)

❌ **Не рекомендуется для:**
- Общих вопросов без специфического контекста
- Креативных задач (написание текстов, генерация идей)
- Случаев, когда база знаний может быть нерелевантной
- Задач с строгим бюджетом на API-запросы

---

### Оптимизация RAG системы

1. **Качество индекса**
   - Регулярное обновление документов
   - Удаление устаревшей информации
   - Тематическая организация (separate indices for different domains)

2. **Настройка параметров**
   - `topK`: 3-5 для большинства случаев
   - `minSimilarity`: 0.5-0.7 (баланс между точностью и полнотой)
   - Chunking: размер чанка 500-1000 токенов с overlap 10-15%

3. **Управление затратами**
   - Кэширование частых запросов
   - Опциональное включение RAG (toggle в UI)
   - Мониторинг использования токенов
   - Использование более дешевых моделей для эмбеддингов (nomic-embed-text - хороший выбор)

4. **Улучшение UX**
   - Показывать источники в UI
   - Индикатор "RAG активен"
   - Возможность отключить RAG для конкретного запроса
   - Превью найденных документов

## Технические характеристики системы

**Векторизация:**
- Модель: nomic-embed-text
- Размерность: 768
- Метрика сходства: Cosine similarity

**Chunking:**
- Размер чанка: 500 токенов (default)
- Overlap: 50 токенов
- Стратегия: word-based с учетом токенов

**Хранилище:**
- Формат: JSON файлы
- Директория: `embeddings_output/`
- Индексация: In-memory при старте сервера

**API:**
- Endpoints: `/api/chat`, `/api/embeddings/rag/*`
- Параметры: `useRAG`, `ragTopK`, `ragMinSimilarity`
- Ответ: `ragUsed`, `ragChunksFound`, `ragSources`
